Inspired by this thread claiming AliExpress was “secretly recording audio.” It isn’t — there is no microphone involved. What it actually does is play a signal you can’t hear and measure your hardware, which is how this page recognizes you. Full explanation →

How it works

1

Play a tone you never hear. The page builds a Web Audio graph (oscillator → compressor) and renders it offline — nothing reaches your speakers.

2

Your hardware leaves a mark. Your CPU, audio stack and drivers round the maths in their own particular way, so the output samples differ device to device.

3

Read the numbers back. The script reads the processed samples directly out of the audio pipeline — digitally, no mic, no permission prompt, no indicator.

4

Hash it into an ID. Mixed with your GPU renderer string, screen, CPU count and timezone, then hashed. That hash is a name tag your browser can’t clear.

 silent tone  ──►  your hardware  ──►  read samples  ──►  sha256  ──►  device id
 (offline)         (CPU/drivers)      (no microphone)                  survives:
                                                                       · incognito
                                                                       · clearing cookies
                                                                       · often a new browser

The hardware id leaves out browser-specific signals so it can survive a fresh profile; the full id adds canvas rendering and is more precise but more browser-specific.

Sites doing this today

From a single instrumented run of 20 major shopping sites (Firefox + Chromium, August 2026). Bot-detection scripts branch per session and region, so treat this as “observed at least once,” not a permanent property of each site.

BehaviorSites
Held a live audio path open to the speakers (zero volume, never closed — this is what broke the original reporter’s Bluetooth) aliexpress.com, ebay.com
Ran the one-shot offline audio hash temu.com, shein.com, shopee.com, dhgate.com, banggood.com, walmart.com, ebay.com
Shipped audio-fingerprinting code that didn’t fire during my visit alibaba.com, lazada.com (same Alibaba script), amazon.com (via AWS WAF)
Other fingerprinting only (canvas, WebGL, device attributes) — no audio taobao.com, tmall.com, wish.com
Nothing observed jd.com, miniinthebox.com

It is not a China story: US eBay held the live audio path open exactly like AliExpress, while Chinese JD.com came back clean. It’s the shared anti-fraud vendors (Alibaba’s fireyejs, HUMAN/PerimeterX, AWS WAF) that spread it — which is also what makes one fingerprint useful for linking you across unrelated sites. No site I tested touched the microphone.
